# 文本脱敏

对用户给出的邮件线程或文章做脱敏。目标是保留原意、事实、时间顺序和论证逻辑，去掉可指向具体人或企业的信息。

不改写观点，不补写原文没有的事实，不把脱敏结果说成已经消除全部重识别风险。

## 输入

- 粘贴文本、文件路径、或邮件导出。
- 未说明范围时，默认：删除全部可识别主体信息，保留产品名、通用地名、金额、数量、日期、条款和论证。
- 用户指定保留或额外删除的项优先于默认规则。

## 识别并处理

先通读原文，建立仅供本次处理使用的实体清单：主体、全部名称变体、替换标签、处理决定。不要将原文或清单发送给外部检索服务；如需落盘，使用私有临时目录，不放入交付物、日志、版本库或持久记忆，完成后清理本次创建的临时副本。

### 删除或替换

- 人名、昵称、职务署名、签名档；企业名、品牌名、第三方客户名、部门名中可识别企业的部分。
- 全称、简称、旧称、称谓（如“王总”“李工”）、拼音/罗马字及中文、韩文、英文等语言变体。能确认属于同一实体的写法必须映射到同一标签；不能确认时分别标注“身份关系未确认”，不要凭相似拼写合并。
- 邮箱（包括单独出现的邮箱本地部分，即 `@` 前的标识）、微信号及其他社交账号、电话、传真、账号、工号、企业域名、可识别主体的网址路径和查询参数。
- 街道地址、楼层、邮编、厂房/园区具体地址。
- 邮件引用头中的身份字段，以及多语言重复的邮件头和签名；主题行里的内部项目代号、客户代号。
- 批号、批准文号/注册证号、CAS 号、PO/订单号、合同号、统一社会信用代码等可精确检索的编号。默认替换为“批次1”“订单1”等稳定标签，保留同号/异号关系；若原值对任务不可替代，先说明风险并询问是否保留，不因其看似技术数据而直接保留。CAS 号通常识别物质，不直接识别企业，但仍按此保守规则处理。
- 间接标识：如“该园区唯一的 GMP 供应商”、罕见职务与城市组合、独家供货关系、可搜索的获奖或项目描述。将可识别部分替换为 `[限定信息已隐去]`，保留其余命题；不要把“唯一”静默改成“之一”。删除会损害核心论证时，询问用户选择保留风险还是进一步隐去。

### 默认保留的内容

- 产品名、物料名、通用技术术语；其中的品牌、企业名和专有代号仍按上节处理。
- 对物流或事实有必要的国家、城市、机场等通用地名。
- 金额、数量、币种、贸易术语、付款条件、交期、批次之间的关系、检验和稳定性结论。
- 日期和相对时间（如“下周假期后”），但应检查精确日期与其他信息组合造成的识别风险。
- 通用法规编号和标准号；能关联具体企业或产品注册的编号不属于此项。

这些保留项仍须接受组合风险检查。若已经构成明显的间接标识，按上节处理；其他保留项在文末说明剩余风险。用户明确指定的保留项应记录为保留例外，不宣称其已脱敏。边界判断和示例见 [脱敏细则](references/redaction-rules.md)。

### 角色标签

- 公司/机构按首次出现顺序使用 A、B、C……；同一机构内人员用 A1、A2、B1……。标签不取自真名缩写，也不随每封邮件的发件/收件方向改变。
- 方向写为 `A1 → B1、C1`，必要时注明脱敏后的抄送对象。所属机构不明的人员用 U1、U2；不推断所属关系。
- 文章可用“甲公司”“乙公司”和“甲公司人员1”等等价方案，但同一文档只用一套。功能称呼只有在不会混淆多个主体时单独使用。
- 文首只解释中性标签及必要的功能角色。默认不附真名对照表；仅用户明确要求时另存，绝不嵌入脱敏正文。

## 邮件线程

1. 拆出每一封邮件的正文，丢掉引用头、签名档和转发包装。
2. 优先依据明确的回复/引用关系按先后顺序重排，不把回复放到提问前面；同层或无回复关系的邮件才按可比较的时间戳排序。
3. 时间戳存在时区差、缺失或与回复关系冲突时，注明排序依据或“顺序未确认”，不编造时间。
4. 每封保留：日期时间、方向（如 `A1 → B1`）、正文；明确要求进一步隐去日期时按用户范围处理。
5. 正文中的错字不静默改正。影响理解时用方括号标注，如 `wee[k]`，不改成另一句话。
6. 重复出现的寒暄可保留一句。广告、免责声明、法律页脚删除。

## 文章

1. 保留标题层级、段落顺序、数据、引用关系和结论。
2. 作者、出处机构、被报道企业、受访者替换为功能标签。
3. 不合并段落，不改数字，不把推断写成事实。
4. 原文有"原因未查明"或不确定表述时照留。

## 复核（交付前必须执行）

1. **格式扫描**：有 Python 3 时，可先对原文运行随附脚本定位邮箱、电话和编号候选；完成替换后必须对最终交付文本再次运行。脚本只标记候选，不自动删改数字。

   ```sh
   python3 <技能目录>/scripts/verify_redaction.py <待交付文件> --aliases <私有别名清单.json>
   ```

   别名清单是待隐去的名称、编号及其已识别变体组成的 JSON 字符串数组，不含用户明确要求保留的例外。脚本检查 `@`、疑似邮箱/电话、数字串、网址、编号关键词、大写开头的英文词及部分中日韩姓名/机构线索，并做 Unicode 规范化、忽略大小写的别名残留匹配。报告仅含类型与位置，不输出命中原文。退出码 0 仅表示无自动命中；1 表示有候选待审查；2 表示输入或运行错误。无 Python 时逐项人工检查，并注明未执行脚本。

2. **逐项裁决**：对每个命中确定为“替换”“按规则保留”或“待确认”。日期、金额、标准号等可能是假阳性，不能为获得零命中而删除必要事实。全部别名残留必须处理；误匹配或保留例外须有依据。修改后重跑扫描，直至没有未裁决项；允许存在已经审查的保留项命中。
3. **原文对照**：逐段对照原文和实体清单，检查遗漏的简称、称谓、跨语言名称、邮箱本地部分、微信号、未映射实体及同名异人。检查标题、说明、脚注、链接目标、文件名和输出格式中的元数据，不只检查正文。脚本无法完整识别人名或确认跨语言实体关系，此步不可省略。
4. **语义和组合复核**：检查间接标识及产品、金额、时间、地点的组合风险；确认标签、回复关系、非标识性数字、条件、否定和不确定程度仍与原文一致。不要为脱敏而改写结论。
5. **复核状态**：全部命中已裁决且语义复核完成，才标记“已复核”；有待确认项则标记“待确认”，不得作为已完成版本交付。扫描失败应修复重跑或改做完整人工复核并披露方式。不把脚本退出码或“已复核”解释为无法重识别。

## 输出

- 短文本直接回复；长文本优先使用用户指定目录，其次使用平台提供的可写输出目录，均无指定时使用当前工作目录下的 `output/`。仅在 Minis 环境可用且无其他指定时，以 `/var/minis/workspace/` 为回退目录。
- 文件名使用不含身份信息的主题和日期。使用当前平台支持的附件或下载链接；仅在支持 `minis://` 的环境提供该协议链接，否则提供实际路径或平台链接。
- 文首用三到五行说明：删除类别、保留类别与例外、角色标签含义、排序规则、复核方式及状态。
- 结尾单独列出实际保留的风险类别及组合（如产品名＋城市＋金额＋日期），不复述已删除的名称、编号或独特描述，也不附原文片段作为复核证据。

## 不做

- 不声称文本已无法被重新识别。金额、时间、产品名的组合仍可能指向具体交易。
- 不把脱敏后的文本用于伪造往来或冒充原作者。
- 不输出被删除的身份信息清单，除非用户明确要求对照表，且对照表与脱敏正文分开存放。

## 完成标准

- 无未处理的主体名称、变体、联系方式、唯一编号或明显间接标识；保留例外已明确披露。
- 话题、非标识性数字、条件、否定和论证与原文一致，标识符替换保留必要的同一性关系。
- 邮件回复关系和时间顺序可读，无重复嵌套引用；角色标签无混用或未经证实的合并。
- 已执行格式扫描或等效人工检查、原文对照和语义复核，全部候选均已裁决，无待确认项。
- 文件名、链接及元数据已检查；交付物不含实体清单、原文片段或真名对照表；本次私有临时副本已清理。
- 已说明复核方式、保留项和剩余识别风险。
