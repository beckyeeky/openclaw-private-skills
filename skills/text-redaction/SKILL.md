# 文本脱敏

对用户给出的邮件线程或文章做脱敏。目标是保留原意、事实、时间顺序和论证逻辑，去掉可指向具体人或企业的信息。

不改写观点，不补写原文没有的事实，不把脱敏结果说成已经消除全部重识别风险。

## 输入

- 粘贴文本、文件路径、或邮件导出。
- 未说明范围时，默认：删除全部可识别主体信息，保留产品名、通用地名、金额、数量、日期、条款和论证。
- 用户指定保留或额外删除的项优先于默认规则。

## 识别并处理

删除或替换以下内容：

- 人名、昵称、职务署名、签名档。
- 企业名、品牌名、第三方客户名、部门名中可识别企业的部分。
- 邮箱、电话、传真、账号、工号、网址中的企业域名。
- 街道地址、楼层、邮编、厂房/园区具体地址。
- 邮件引用头：From、To、Cc、Date、Subject 中的身份字段；韩文、中文、英文重复的邮件头和签名。
- 主题行里的内部项目代号、客户代号。

默认保留：

- 产品名、物料名、通用技术术语。
- 国家、城市、机场等对物流或事实有必要的地名。具体街道地址删除。
- 金额、数量、币种、贸易术语、付款条件、交期、批次、检验和稳定性结论。
- 日期和相对时间（"下周假期后"）。时间用于重建顺序，不单独构成身份信息。

同一文档内替换标签保持一致。需要区分角色时使用中性标签，并在文首说明：

- 邮件：A＝发件/报价方，B＝收件/询价方。第三方用"终端客户""检测机构"等功能称呼，不用真名。
- 文章：用"甲公司""乙公司"，或"该企业""该公司"。首次出现时建立对照，后文不换标签。

对照表只在用户要求时附上。默认交付物不含真名对照，避免脱敏文件本身重新暴露身份。

## 邮件线程

1. 拆出每一封邮件的正文，丢掉引用头、签名档和转发包装。
2. 按时间升序重排。原始导出通常是倒序嵌套。
3. 时间戳有时区差时，按回复层级排序，不按表面时间戳把回复放到提问前面。
4. 每封保留：日期时间、方向（A → B）、正文。
5. 正文中的错字不静默改正。影响理解时用方括号标注，如 `wee[k]`，不改成另一句话。
6. 重复出现的寒暄可保留一句。广告、免责声明、法律页脚删除。

## 文章

1. 保留标题层级、段落顺序、数据、引用关系和结论。
2. 作者、出处机构、被报道企业、受访者替换为功能标签。
3. 不合并段落，不改数字，不把推断写成事实。
4. 原文有"原因未查明"或不确定表述时照留。

## 输出

- 短文本直接回复。
- 长文本写入 `/var/minis/workspace/`，文件名含主题和日期，回复中给出 `minis://` 链接。
- 文首用三到五行说明：删除了什么、保留了什么、角色标签含义、排序规则。
- 结尾单独列出仍保留、但可能指向身份的项（产品名、城市、机场、金额组合）。用户要求进一步隐去时再替换，不默认删除。

## 不做

- 不声称文本已无法被重新识别。金额、时间、产品名的组合仍可能指向具体交易。
- 不把脱敏后的文本用于伪造往来或冒充原作者。
- 不输出被删除的身份信息清单，除非用户明确要求对照表，且对照表与脱敏正文分开存放。

## 完成标准

- 正文中不再出现人名、企业名、邮箱、电话、具体街道地址、签名档。
- 话题、数字、条件和论证与原文一致。
- 邮件按时间或回复层级可读，不残留嵌套引用。
- 已向用户说明保留项和剩余识别风险。
